# Decisions

- Dates: `kal` and `porshu` are ambiguous. The parser defaults to the past (yesterday, or the day before yesterday) and sets `ambiguous=true` with both candidates. Completed work is never silently given a future date.
- Incentives: amounts stay null and `verified` stays false. The loader raises an error if an amount is set while unverified.
- Names: full names are reduced to initials in notes and `beneficiary_ref`. An `ID <n>` pattern takes precedence as the reference.
- Time zone: all date and time logic uses Asia/Kolkata. `tzdata` is a runtime dependency because Windows has no built-in IANA database.
- Timestamps: `created_at` is stored as naive IST wall-clock time, because SQLite has no timezone support.
- Extractor: rules-based only (`LLM_PROVIDER=rules`). Clauses are split on punctuation and conjunctions. Clinical keywords return a fixed refusal, not an answer.
- Lexicon: `config/lexicon.yaml` is a first draft and needs native speaker review.
- Gnani: `docs.gnani.ai` returned HTTP 403, so the API format is unknown. `GnaniPrismaSTT` and `GnaniTimbreTTS` are stubs that raise `NotImplementedError` with a TODO. Nothing is guessed. The turn endpoint returns 503 when a Gnani provider is selected.
- Dialogue: `handle()` is pure. It takes the session state and returns a reply, the new state, and the entries. It persists nothing. `/api/turn` saves entries only on a confirmed "yes".
- Confidence gate: a field below its threshold is left empty and asked again, so low-confidence entries are never saved without confirmation.
- Sessions: an in-memory store with a TTL (`SESSION_TTL_SECONDS`, default 900). Restarting the server clears sessions.
- Rate limit: in-memory, per client IP, `RATE_LIMIT_PER_MINUTE` (default 30).
- Audio: the mock STT reads text from the request. Uploaded audio is held in memory only and is never written to disk, so there is nothing to delete unless `STORE_AUDIO=true` (not implemented, since no storage path is needed yet).
- Extractor fix: a bare count clause such as "2 jon" after a task clause now sets the previous entry's count, instead of creating an `other` entry.
- Extraction evaluation pipeline: `eval/run_extraction_eval.py` evaluates single-turn utterances directly through the extractor (verifying NLU extraction and clinical refusal) and multi-turn dialogues through `DialogueManager.handle` turn-by-turn. When a dialogue reaches confirmation and is saved via "yes", `res.entries` contains the completed drafts (which `state.drafts` clears on transition back to IDLE), so the evaluation captures the final saved records.
- Noise mixing: `eval/add_noise.py` relies solely on standard library `wave` and `numpy`. Noise is repeated or sliced to match clean audio length, scaled to the exact desired SNR in dB via power ratio calculation, and clamped to 16-bit integer bounds without third-party audio packages.
- STT evaluation tool: `eval/run_stt_eval.py` groups audio files by noise level (inferred from parent directory or filename pattern) and calculates Word Error Rate using `jiwer`. For `MockSTT`, reference transcripts are mapped to mock output to verify tooling execution; the output is prominently flagged as "tooling check only, NOT a real speech-accuracy result".
- Git audio safety: `eval/audio/` was explicitly added to `.gitignore` to guarantee that no local or temporary synthetic audio recordings are ever committed.
- LLM comparison benchmark: Verified that `apps/api/app/nlu/llm.py` and `tests/test_llm.py` enforce temperature 0, strict Pydantic schemas (`extra: forbid`), fallback to rules on failure/timeout, logged reasons without personal data, and provider plus latency timings. Because no `OPENAI_API_KEY` was configured in the environment, the comparison benchmark was not run, adhering strictly to working rules.
- Smoke scripts: `scripts/smoke.sh` and `scripts/smoke.ps1` spin up the API with a temporary SQLite database (`DATABASE_URL=sqlite:///...`), poll `/api/health`, run an end-to-end 3-turn conversation via `POST /api/turn`, verify confirmed persistence via `GET /api/entries`, and guarantee server shutdown and database cleanup in a `finally`/`trap` block. On Windows PowerShell, `Stop-Process` is used instead of `$proc.Kill(bool)` for compatibility with Windows PowerShell 5.1.
- Root `main.py` cleanup: Inspected root `main.py` (0 bytes, unreferenced leftover). Recommended its removal while strictly preserving it without deleting per the working rule constraint. Verified that `.gitignore` already covers build artifacts (`*.tsbuildinfo`, `node_modules/`, `.next/`, `*.db`).
- Gnani HTTP Client: Used `httpx` directly instead of adding the Gnani SDK. Moved `httpx` from `requirements-dev.txt` to production `requirements.txt` to keep dependencies minimal.
- Bengali Spoken Numbers: Implemented `number_to_spoken_bn` in `apps/api/app/speech/spoken_bn.py` to convert bare digits into Bengali spoken words before TTS synthesis (handling 0-100, years, ordinals, and currency). Marked regional variations with `# NEEDS NATIVE SPEAKER REVIEW`. Non-numeric text is left untouched.
- Pre-send STT Validation: Rejected WebM format (HTTP 415) and audio longer than 30 seconds (HTTP 413) before dispatching network requests to save Gnani API credits and bandwidth.
- Concurrency & Retry Strategy: Outbound Gnani calls are wrapped in a `threading.Semaphore(GNANI_MAX_CONCURRENCY)`. Retried 429 and 5xx errors up to 2 times with exponential backoff (0.5s, 1.0s); client errors (400, 401, 402, 403, 422) fail immediately without retry.
- Asymmetric Failure Policy: If STT fails, `/api/turn` returns a clear bilingual error and prompts the user to type; it never silently falls back to MockSTT. If TTS fails, `/api/turn` safely falls back to client browser TTS with `tts_fallback: true` in the response payload and logs a warning.
- TTS Disk Caching: Cached synthesized audio on disk using SHA-256 signatures of `(model, voice, language, speed, sample_rate, container, processed_text)` in `TTS_CACHE_DIR` (`.cache/tts`), added `.cache/` to `.gitignore`.
- Privacy-Safe Logging: Outbound Gnani logs record only `request_id`, `model`, `latency_ms`, and `status`. API keys, raw audio byte buffers, and transcript texts are never logged.
- Test Isolation & Live Safety Guard: Unit tests mock all network calls via `httpx.MockTransport`. Outbound live calls are blocked unless `allow_live=True` or an explicit test transport is injected. Live test scripts in `scripts/` require an explicit `--yes` confirmation flag.
